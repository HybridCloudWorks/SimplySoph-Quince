# WhatsApp Activation Review

Treat the sender and template status below as unverified until re-checked through the Twilio API (see [twilio-setup.md](twilio-setup.md)). WhatsApp operates independently of the SMS A2P campaign, which Twilio approved in October 2026 after a 30909 rejection and resubmission. International guests receive a household-specific private website link; replying in WhatsApp does not submit an RSVP or sign into the website.

## Consent And First Invitations

WhatsApp is optional and separate from email and SMS. Guests with a private invitation can open My Account, enter an international-format phone and language, and explicitly request WhatsApp updates. They must then send START from that phone to verify it. Saving a form alone never enables sending.

For a guest who has not received an invitation yet, the organizer can record explicit WhatsApp permission in Notion: WhatsApp Phone, Language (en/es), Consent, Consent Date, Consent Source and Consent Version. Record actual evidence, not an inferred opt-in. Ask the guest to read /whatsapp/ and send START to +16827868002. A matching consent record and verified incoming message are required before the admin sender includes them. Merely adding a number is insufficient.

STOP/BAJA blocks WhatsApp sends locally even during Notion outages. Pending changes remain blocked until projection succeeds. Admin Retry sync recovers failed projections. Phone changes require new verification. Shared phones are deduplicated per campaign.

## Templates

Four text templates were submitted to Meta on September 28, 2026: invitation_en, invitation_es, reminder_en, reminder_es. All were submitted as MARKETING. Current approval must be checked through the Content API before activation. The first follow-up check showed three pending and reminder_es rejected with an unknown rejection reason; rejected templates must not be used.

Templates use one variable: the private household URL generated by the server. Public examples contain no real invitation tokens. Admin drafts encrypt private URLs at rest, bind them to the active invitation generation, and require fresh consent and recipient review before dispatch. Failed or uncertain attempts are not automatically resent.

What Meta rejected along the way, so it is not repeated:

- A template submitted without a sample value for `{{1}}` fails ("component of type BODY is missing expected field(s) (example)").
- Wording such as "private link", "Keep this link private" or "No compartas este enlace" makes Meta classify a Marketing template as Authentication ("Category mismatch"). Twilio shows only "Unknown rejection reason". Meta's own reason is in Business Support Home (Account Overview → View my accounts → the WhatsApp account → Rejected message templates) or in the rejection email.
- Samples avoid special characters such as `#`. Real links still carry `#` and the private code.
- A rejected or deleted template's name cannot be reused for up to 30 days, so resubmissions use new names.

Once Meta approves them, send the four `HX…` Content SIDs for the `WHATSAPP_TEMPLATES_JSON` update. The server refuses to start with WhatsApp switched on while an approved template shows a date other than the current RSVP deadline, so the old templates can never go out with the wrong day.

### Owner action: the Spanish deadline wording (optional resubmission)

The approved Spanish templates say "Confirma tu asistencia **antes del** 15 de noviembre de 2026". In Spanish, "antes del 15" leaves the 15th out, while the English says "by November 15" and the RSVP stays open until 11:59 PM that day (Fort Worth time); the website says "a más tardar el" (round 2 wording review, L10N-09). The code keeps sending the approved text exactly, because a template must match what Meta approved. Meta currently blocks marketing-template delivery to US numbers. A US owner can test verified inbound opt-in/help/opt-out replies; full international invitation delivery needs a separately authorized eligible non-US test recipient. Do not classify invitations as utility to bypass this restriction.

## Configuration And Acceptance

Runtime uses the existing Twilio account, a restricted API key, and pinned Auth Token for signatures. Configure WHATSAPP_FROM=+16827868002, WHATSAPP_TEMPLATES_JSON, WHATSAPP_ENABLED and WHATSAPP_ACTIVATION_REVIEWED separately from SMS. Activation stays off until provider approval and acceptance testing. Secrets never belong in Git or browser JavaScript.

Routes /api/whatsapp/inbound and /api/whatsapp/status validate signatures and the exact channel/sender. SMS callbacks remain separate.

1. Verify ONLINE sender and approved templates through the provider API.
2. Test owner START, HELP, STOP and re-subscription from the actual phone.
3. Check Notion projection and local suppression.
4. Preview one eligible international test recipient and private link.
5. Enable restricted sending only for an authorized acceptance test; verify delivery, website RSVP, Notion and receipt email.
6. Enable reviewed dispatch after these checks; SMS is switched on and off separately, as described in [twilio-setup.md](twilio-setup.md).

February 1, 2027 is review/export, not automatic deletion. Inventory templates, consent records, callbacks and credentials for reviewed cleanup. Preserve shared Twilio/Meta accounts and the owner-provided number.
